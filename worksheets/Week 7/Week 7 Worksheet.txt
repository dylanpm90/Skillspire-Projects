Concepts & Basics 

 1   In one sentence, define a database transaction and why it matters (use the bank transfer example). 

It groups a statement such that they fail or succeed together, or atomicity. For example, if a bank account transfers money from one account to another, the sequence of operations are rolled back if a part fails, making the transaction secure and keeping the total sum of funds the same.

Consistency - data moves from one valid state to another.
Isolation - other users never see half completed work.
Durability - once committed, a change survives a crash.

 18   Briefly describe NESTED. When might it be helpful? 
A NESTED propagation transaction runs inside an outer transaction. If the inner transaction fails, it rolls back to a certain save point if the rollback rules are established. The outer transaction, however, still commits.
A storerunner is running a promotion, spend $50 or more and you get a free gift bag. The customer create a new order but the customer only spends $20. So the inner nested transaction of meeting the threshold to get the giftbag and subtracting that from the giftbag inventory fails, but the order(an outer transaction) still goes through.

Isolation Scenarios 


36    Two concurrent transactions read and update the same row. With READ_COMMITTED, can a transaction see an uncommitted change? 

It cannot, READ_COMMITTED prevents "dirty reads".


37     Name an anomaly that REPEATABLE_READ prevents but READ_COMMITTED does not. 

READ_COMMITTED can read the same row twice and receive two different values and REPEATABLE_READ prevents this.


38     Give a case where SERIALIZABLE is worth the cost (1–2 lines). 

When two customers are attempting to book the same seat on a flight, because SERIALABLE does transactions one at a time, this will help prevent overbooking.
