Concepts & Basics 

    In one sentence, define a database transaction and why it matters (use the bank transfer example). 

It groups a statement such that they fail or succeed together, or atomicity. For example, if a bank account transfers money from one account to another, the sequence of operations are rolled back if a part fails, making the transaction secure.

Atomicity - all or nothing. 
Consistency - data moves from one valid state to another.
Isolation - other users never see half completed work.
Durability - once committed, a change survives a crash.

It makes a save point to rollback to in the transaction. It lets an outer transaction occur while an inner transaction is rolled back.
 


Isolation

    READ_COMMITTED → prevents dirty reads 

    REPEATABLE_READ → prevents non-repeatable reads 

    SERIALIZABLE → prevents phantom reads

Programmatic Transactions 

    Fill in a TransactionTemplate example: 

@Autowired 
TransactionTemplate txTemplate; 
@Autowired 
JdbcTemplate jdbc; 
public void pay(long id, double amt) { 
txTemplate.execute(status -> { 
jdbc.update("UPDATE users SET credits = credits - ? WHERE id = ?", amt, id); 
Double amt = jdbc.queryForObject("SELECT balance FROM accounts WHERE id = ?", Double.class, from);
            if (amt == null || amt < 0) {
                status.setRollbackOnly();   // undo the UPDATE at the end, without an exception
               
            }
            jdbc.update("UPDATE accounts SET balance = balance + ? WHERE id = ?", amt, to);
 
        });
return null; }); 
}

Rolls back without throwing.
