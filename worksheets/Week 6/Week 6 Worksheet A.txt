16. Given:

class Server { String region; }
class Cluster { /* fill */ }

Compose Cluster so it holds many Servers (field + add method).

import java.util.ArrayList;

public class ServerClusterComposition {

    class Server {
        int serverNumber;

        void ping() {
            System.out.println("Server ID#:" + serverNumber + " - Pinged!");
        }

        Server(int serverNumber) {
            this.serverNumber = serverNumber;
        }
    }

    class Cluster {
        String regionName;
        ArrayList<Server> serverCluster = new ArrayList<>();

        Cluster(String regionName) {
            this.regionName = regionName;
        }

        void addServer(Server server) {
            serverCluster.add(server);
        }

        void pingServers() {
            for (Server server : serverCluster) {
                server.ping();
            }
        }
    }
    
    void main(String[] args) {
        System.out.println("New Server Cluster:");
        Cluster cluster = new Cluster("PNW");
        cluster.addServer(new Server(123));
        cluster.addServer(new Server(456));
        cluster.addServer(new Server(789));
        cluster.addServer(new Server(101112));
        cluster.pingServers();
    }
}

20. Replace #19 with a safer composition: class Report has a private List<String> and forwards add + size.

import java.util.*;

public class ReportComposition {

    class Report{
        private ReportList reportList = new ReportList();

        void addToReportList(String listItem){
            this.reportList = reportList;
            reportList.addToReportList(listItem);
        }
        int reportListSize(ReportList reportList){
            this.reportList = reportList;
            int reportListSize = reportList.listSize;
            return reportListSize;
        }
    }

    class ReportList{
        String listItem;

        List<String> list = new ArrayList<>();
        int listSize = list.size();

        void addToReportList(String listItem){
            this.listItem = listItem;
            list.add(listItem);
        }
    }

    void main(String[] args) {
        Report report1 = new Report();
        report1.addToReportList("Laptop");

        System.out.println(report1.reportList.listItem);
    }
}

25. Short case: You need two payment engines (Card, Crypto) with the same API and hot-swappable at runtime. Choose inheritance or composition + interface? Sketch the approach.

Composition is preferred. There are two classes, one for each payment option. When the user chooses an option, the methods from the respective class is invoked. Inheritance wouldn't make as much sense here although it is conceivable to have a broader abstract parent "Payment" class from which some basic structure derives, like account numbers and balance variables or saved profile information, since both Crypto and Card may or may not have that information.
