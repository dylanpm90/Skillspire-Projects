2. Create an abstract Vehicle with fields vin, model, year and abstract diagnostics(). Provide a protected constructor.

abstract class Vehicle {
    private final String vin;           // final: set once in the constructor, never changed
    private String model;
    private int year;

    protected Vehicle(String vin, String model, int year) {   // protected: children and the same package can call it
        this.vin = vin;
        this.model = model;
        this.year = year;
    }

    public String getVin() { return vin; }
    public String getModel() { return model; }
    public int getYear() { return year; }

    public abstract void diagnostics();

9. Build ChargingStation with location and a boolean available defaulting to true. Implement startCharging(TeslaCar) and stopCharging() such that only one car can charge at a time.

class ChargingStation {
    private String location;
    private boolean available = true;   // private: only startCharging and stopCharging change it

    ChargingStation(String location) {
        this.location = location;
    }

    void startCharging(TeslaCar car) {
        if (available) {
            System.out.println("Charging Tesla " + car.getVin() + " at " + location);
            available = false;
        } else {
            System.out.println("Station busy at " + location);
        }
    }

    void stopCharging() {
        available = true;
    }
}

30. Reflection: Choose one place where you “favored composition over inheritance” and justify the decision in 2–3 lines.

In a game I'm making, I'm trying to implement composition over inheritance using state machines. Characters and enemies and the players can share states such as Idle, Jump or Running and I have classes which reflect as much. Rather than having Characters and the Player inherit all those capabilities from a larger abstract class (though that's useful in other situations, such as health or stamina or other stats), it's more practical to implement a state machine for all those abilities.
